# MDagent 网页可视化与低带宽轨迹设计

日期：2026-10-12。状态：`DESIGN_APPROVED_FOR_PLANNING`。用户已在本会话确认“设计符合，继续写实施计划”；该确认批准本设计进入实施计划，不代表功能已实现、部署或性能已通过。

## 1. 目标与首版范围

在现有 MDagent 的 Bio 网页中查看输入结构、已接受的结果结构和轨迹；用户可以旋转、选择、调整表示方式、播放、暂停和定位时间。继承 KSH 的交互与来源规则，并让 Agent 获得当前视图的结构化观测、通过限定操作控制当前视图。

用户已确认采用网页交互，服务器带宽约为 5M。本设计按 **所有用户共享 5 Mbps 公网出口** 处理，不假设每个用户都有 5 Mbps，也不假设最终计算节点可以从浏览器直连。

首版包含：结构预览、轻量全程轨迹、局部详细轨迹、鼠标与 Agent 共用显示操作、视图恢复、来源展示、缓冲与带宽管理。以现有 Bio/OpenMM 科学范围为限。

分析曲线联动、结构叠合、体积图、PyMOL 正式出图和模型截图反馈留给后续子项目；首版不扩展模拟或参数化的科学范围。

## 4. 轨迹数据关系与预览生成

预览生成在最终计算节点执行，是有资源上限的已有数据派生任务，不启动 MD、不产生科学执行授权。使用固定函数和字段，不接受 Shell、Python、JavaScript 或任意 MDAnalysis 选择表达式。

- 输入结构只能引用该会话导入目录的现有输入记录；轨迹只能引用该项目已完成且具有接受记录的 attempt。
- 同一已接受 attempt 的原始拓扑、DCD 分段、时间文件、模型和接受记录构成同一 `sourceRef`。分段次序与帧时间来自已验证元数据，不按文件名字符串排序推断，不将阶段本地帧号冒充全局帧号，也不自动跨阶段拼接。
- 核对原子数、源原子顺序、有限坐标、时间文件行数与单调性、盒向量、长度和时间单位。同一源内时间重复或倒序拒绝生成轨迹预览，时间间断和实际末帧明确标注。
- 协议中 `sourceFrameIndex` 与 `segmentFrameIndex` 从 0 开始，界面计数从 1 开始；分段引用和实际时间同时保留。只有 1 帧时显示静态结构，暂停多帧播放控件。
- 建立 `previewIndex -> sourceAtomIndex` 映射，并绑定源拓扑哈希；PDB serial、行号和渲染器 index 不能单独作为源身份。
- 原始结构、DCD、分析结果和 checkpoint 保持原样。质心平移、对齐、PBC 处理如另行开放，必须是显式派生选项并记录算法与参考，首版不默默改变坐标。

首版有两级显示：

| 级别 | 内容与规则 |
| --- | --- |
| `overview` | 蛋白采用 Cα 骨架线/管，加模型已识别配体的重原子；独立小分子采用其重原子。默认省略溶剂的实际传输，界面明确显示原子子集。Cα 视图不声称重建完整二级结构。全程最多 200 个真实源帧，包含首末帧，索引唯一且有序 |
| `detail` | 用户选定时间窗和已定义原子集合后取详细坐标，保留真实帧映射。源帧密度不足时显示实际数据范围；不生成插值帧冒充计算帧 |

纯水盒先提供结构与周期盒视图；全水轨迹作为用户明确选择的详细视图。没有有效骨架或模型角色信息时，不擅自猜配体或随机省略原子；显示原因并提供可用的明确集合。

预览坐标使用分段 XTC，每段配套匹配的子集拓扑、源帧索引、真实 `timePs` 和盒信息。编码精度固定为 `precision=3`，即 XTC 原生 nm 坐标的 0.001 nm 刻度；记录量化精度并在验证中检查往返误差。它是可视化派生产物，正式分析仍从原始接受文件执行。

`previewKey` 包含完整来源描述、原子集合、源帧选择、编码精度及派生实现身份。同一来源与配置复用同一预览；视角或颜色变化不重新复制轨迹。源文件变化后旧预览失效，保留旧数据并明确报错。

## 5. 协议与浏览器行为

小型控制请求继续使用原会话 RPC；坐标通过同源鉴权二进制通道返回。最终节点到控制服务器可继续使用现有受限 Bridge 分块，出口通道不再把坐标编码成 Base64 JSON。不因增加二进制出口而扩大旧下载协议的权限或限额。

预览协议 `bio.preview.v1` 仅允许这些概念操作：`describe` 获取来源、`prepare` 请求固定派生、`status` 查看派生状态、`window` 选择时间窗、`read` 获取已校验分块、`cancel` 取消自己的待处理取数。派生异步执行，长转换不占用审批、取消或恢复请求的队列。

描述中必须包含：租户/会话/目标绑定、source/preview 哈希、原子映射、实际源帧数、每个预览帧的源帧与时间、抽样说明、精度、分块尺寸/摘要及生成状态。请求仅使用服务器签发的来源和预览引用；不由浏览器指定计算路径或他人租户。

二进制路由逐请求重验原账号、Bio 会话、节点与目标权限，异步处理后再次检查绑定；令牌不进入 URL。复用原已认证租户入口，Host/Origin 校验不替代用户认证。断线重试按引用和块索引幂等，来源变更、权限撤销及对象替换均拒绝旧请求。

网页在现有对话旁提供可折叠的 3D 工作台：上传后可打开输入；用户查看已接受阶段时打开对应结果。默认选择唯一明确来源，多来源时显示来源选择。原任务审阅与提交入口继续可用。

显示操作 `bio.view.v1` 至少支持 `openSource`、`setRepresentation`、`select`、`focus`、`seekTime`、`play`、`pause`、`observe`。鼠标与 Agent 共用处理器；命令携带 viewport 与其依赖的版本，过期操作返回冲突，不能重新绑定到用户后来打开的对象。

Agent 的完成回执必须来自已连接视图实际加载的来源、原子映射与当前源帧。离线、多窗口歧义、解码失败和未到达目标帧不能报告操作成功。显示观测不构成科学产物接受或新的计算权限。

视图保存来源引用、原子集合、表示、相机、真实源帧、播放范围和速率；不保存坐标副本。首版每个会话维护当前视图状态，不按每帧追加历史。刷新后验证引用再恢复，源失效时保留记录并提示。首版坐标缓存在浏览器内存，离开会话停止预取；不跨租户共享缓存或在本地长期保存完整科研数据。

## 6. 5 Mbps 预算、调度与空间

5 Mbps 的理论二进制上限为 625,000 B/s；Base64 单独就会将对应有效载荷上限降至约 468,750 B/s，均未扣网络和其他请求开销。

| 初始策略 | 设计值 |
| --- | --- |
| 共享预览出口预算 | 全部署聚合最多 4,000,000 bit/s；给其他请求留出余量。单一全局裁决点覆盖所有租户，不能让每个租户分别领取 4 Mbps；多 API worker 必须共享裁决状态，否则拒绝启用聚合限速功能 |
| 调度顺序 | 首次显示及当前定位优先，后台预取其次；同级按活动视图公平轮转。每视图最多 2 个在途请求，取消和权限检查不受大文件队列阻塞 |
| HTTP 预览块 | 目标 <=256 KiB，硬上限 1 MiB，且每段为可独立校验和解码的坐标内容；一个帧已超限时明确请求更小集合，不截断原子 |
| 内存窗口 | 每窗口最多 64 帧，解码坐标 <=32 MiB；当前与预取窗口合计 <=64 MiB。分配前按 `12 * atoms * frames` 及实际解码结构估算，浏览器完整占用另测 |
| 播放 | 默认 10 个真实预览帧/s，可选 1–20。先缓存，再播放与预取；无下一帧时停在最后确认帧并显示缓冲。详细模式不静默降低源帧密度，可降低播放速率或等待缓存 |
| 全程预览 | 最多 200 帧；通过更稀疏的真实时间采样降低总量，页面明确显示抽样。索引和初始坐标先返回，不要求完整全程下载完才显示结构 |
| 预览存储 | 每计算项目新增预览上限 256 MiB；超限拒绝新增，报告已有占用，不自动删除历史、原始轨迹或恢复点。每租户并发派生最多 1 个，CPU/内存必须纳入目标允许的资源策略 |
| 静态前端资源 | 哈希版本、压缩、可缓存、按需加载；单独记录新增压缩 JS/CSS 大小。Mol* 冷加载计入首次访问验收，不用已缓存结果代替冷启动 |

已有预览按内容身份复用；每次相机或帧操作只更新小元数据。取消、磁盘满、进程崩溃将本次临时状态标记为中断，失败残留计入配额并列为后续授权清理候选，已发布预览与科研数据不删除；不在本功能中增加广泛清理或跨项目共享目录。

缓冲不能解决长期数据消费超过有效带宽的问题。持续取数不足时，先减少后台预取，提示等待或选择较轻的明确预览；不假设更换播放器可以突破总带宽。

## 7. 验证与验收

性能数字是待实施目标，必须保留实际测量值；本轮没有限速实验、真实网页验收、远程运行或新 MD 计算。

| 验收层 | 必须提供的证据 |
| --- | --- |
| 数据正确性 | 源哈希、原子映射、分段拼接、真实末帧与时间、单位及盒信息检查；XTC 往返坐标误差 <=0.01 Å，时间映射保留 sidecar 真值；科学原文件前后哈希一致 |
| 错误路径 | 错配拓扑、损坏块、源变更、权限撤销、错误租户、会话替换、迟到响应、取消、断线重试、配额/磁盘不足均不误报成功或重复生成派生 |
| 交互 | 结构打开、选择/表示、轨迹暂停/播放/定位、用户旋转后继续播放、Agent 操作回读、刷新恢复、两个会话切换完整走通 |
| 单用户网络 | 共享出口限为 5 Mbps，另测 100 ms RTT；参考蛋白约 300 个残基及小配体。从已打开的 Bio 网页发起预览，预览已生成且可视化静态资源已缓存时，首次有效结构目标 <=4 s、首次播放目标 <=6 s；可视化资源首次冷加载显示目标 <=12 s。整站初访耗时另报 |
| 持续与并发 | 1/3/5 个视图共享同一 5 Mbps 出口各运行 180 s。轻量全程预览缓存后的卡顿时间目标 <=1%；记录每用户吞吐、等待、帧正确性、公平性和出口聚合值，不能对每个连接各限 5 Mbps |
| 大轨迹 | 使用已有合规真实轨迹和标明工程用途的有界压力数据，覆盖约 10 万原子、长帧索引和频繁跳转。测派生冷启动、峰值内存/磁盘和取消；不为性能试验启动长程生产 MD或下载大型新数据集 |
| 性能边界 | 首次预览派生等待、完整原子密集窗口和弱设备另行报告。上述参考目标不宣称任意全水体系或任意并发都能即时高清播放 |
| 原功能回归 | 原 Bio 合法/撤销会话、人工审批/提交分离、下载完整性、远程生命周期与 scoped-session 正反例仍通过 |

短工程轨迹或合成压力数据可以证明传输与显示行为，不能证明科学采样充分。生产多租户、真实计算节点和部署带宽验收单独记录。

## 8. 推进顺序与审阅事项

设计审阅后再写实施计划。按可独立验证的交付推进：预览契约与固定派生；同源鉴权二进制转发及共享预算；网页 Mol* 适配与 KSH 控件复用；Agent 显示回执与恢复；5 Mbps 限速及回归验收。每步都保留来源和失败路径证据，不自动 commit、push 或部署。

本次供用户审阅的具体选择：网页交互与 Mol* 浏览器适配；全程默认骨架/配体并明确抽样；原始 DCD 保留；详细时间窗按需取数；4 Mbps 聚合预览预算；首版不加入图表联动与 PyMOL 正式出图。新增依赖安装和真实部署分别安排，不由本设计文件隐含批准。
