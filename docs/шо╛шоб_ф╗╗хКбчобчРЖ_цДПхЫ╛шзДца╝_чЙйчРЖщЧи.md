> 来源:设计工作流 md-taskmgr-intentspec-design(2026-08-18)产出 + 两镜头对抗校验(冲突/物理+红线)。

## 0. 核心原则(三分树,物理隔离)

- **AGENT_BASE**(harness 代码) ∥ **RUN_CASE_BASE**(LAMMPS 真相源产物,编排器管) ∥ **PROJECT_ROOT**(agent 的意图/规划工作区,新增)。三者物理隔离。
- **只读 mdsim 桥保持零写**,只认 `local_base`(模拟真相源)。**绝不**给它加 PROJECT_ROOT 分支(校验高危#1:ssh 模式下 agent 端 PROJECT_ROOT 在 Windows、够不到 remote_base)。
- **另设一个与只读桥【分离】的受控写 MCP**(serverName 如 `mdproj`),只做两件事:①`project_root 内 mkdir` ②`写 *.json 骨架`。它有自己的 config(PROJECT_ROOT 键放这里,**不进 md_config.json**)。
- agent 的"项目/任务文件夹"是**规划工作区**,不是 LAMMPS 运行目录;prod_dir 仍由编排器落 RUN_CASE_BASE,agent **只引用指针不搬动**。

## 1. 文件夹层级

```
PROJECT_ROOT/                                   # 写 MCP 自己的 config 键(非 md_config.json)
└── <project>/
    ├── project.json                            # {project, created, case_ids[], registry_refs[]}
    ├── 归纳说明.md                              # ★自动生成(见 §6),文件数/大小实测
    └── <run_folder>/                           # run_folder = <case_id>_<YYYYMMDD>_<HHMMSS>(仅 agent 本地标识)
        ├── intent.json                         # 结构化意图规格 + 门校验报告
        ├── 归纳说明.md                          # ★自动生成
        ├── inputs/                             # 拟提交的 production.in/data 草案(非真相源,不执行)
        ├── logs/                               # 起草/确认/门校验/审计流水
        └── results/                            # 只读软链回 RUN_CASE_BASE(★禁止任何写原语穿透,见§5)
```

**命名纪律(校验 med#4/low#5)**:
- `intent.case_id` = **语义 case_id**(如 `network_6000`,对齐 status_bus 键 / state.task.case_id)。
- `run_folder` basename = **agent 工作区本地标识**,**不保证**等于 prod_dir basename(编排器运行时另生成时间戳、date 层=运行日、二次隔离会再改名)。
- **跨系统唯一可靠连接 = `intent.prod_dir_ref` 绝对指针**。**agent 绝不反推 prod_dir 路径**(date 层不可预知);prod_dir_ref 在编排器二次隔离后需可刷新。

## 2. intent.json schema(要点,完整字段见工作流产出)

以 `case_id` 为公共外键,对齐 state.task + system_spec.schema + sim_config.schema。关键字段:
- `schema_version/case_id/project/created/status`(DRAFT|CONFIRMED|GATED_PASS|GATED_FAIL)/`reproduce_or_improve`
- `source`(Mode B read_paper 出处:paper_path/doi/reported_method)
- `system`(molecule / **target_elements** / size.density_target / **declared_net_charge** / packmol_input)
- `objective`(simulation_goal[对齐 system_spec 枚举] / target_property / key_values+出处)
- `constraints`(temperature_range / **declared_density_range** / **protocol_flags{is_quench,has_heating_ramp}** / walltime / cores)
- `ensemble_sequence`[](有序:minimize→pre_equil(nvt/langevin)→production(npt);**H2/H3 判定的唯一真相源**)
- `key_params`(timestep_fs / total_steps / cores / forcefield{preferred,fallback} / units / pair_style)
- `prod_dir_ref`(str|null,运行后回填,**唯一跨系统链接**)
- `gate_report`(passed / hard_violations / soft_warnings / checked_at)

## 3. 物理常识门(已修正)

**硬门(违反必拦,不给方案)**:
- **H1 timestep**:units **real** 时 timestep>0.25fs 拦(一般)、>0.1fs 拦(压缩/成键断键反应/高应变);units metal 时 >0.25/0.1×1e-3 ps 拦。与 ensemble_sequence 工况交叉核对。〔校验 low#6:补齐 real 主路径判据〕
- **H2 非平衡/碎片起点禁裸 NVE**:以 `ensemble_sequence` 为真相源——production 前无 minimize 也无控温(nvt/langevin/rescale/berendsen)则拦。〔**续跑豁免**:检测到 read_restart/read_data 且体系标注来自 CONFIRMED 前置平衡态 → 视为 continuation 不拦,校验 med#3〕
- **H3 非平衡起点禁 NPT 硬压(已修正,校验 high#1)**:决定性阻断 = **首个动力学段即 NPT AND 前无 minimize 与控温 AND 起点为非平衡/碎片(dmin 小 / 密度远离平衡簇 / packmol 未弛豫)——任意压强(含 1atm)都拦**。压强量级**不是**必要条件(去掉原 ≥100atm 阈值,否则实测 1atm 碎片化事故漏拦)。≥100atm 作为并列的充分条件(即使有弛豫也警示)。
- **H4 近距接触**:对 data 按周期算 dmin;<0.8Å 且无 minimize/soft 预处理则拦,<0.3Å 一律拦(金属短键须 intent 显式声明)。
- **H5 净电荷(已修正,校验 med#5)**:求 data 电荷和,与 `declared_net_charge` 比,`|Σq−声明值| < 固定小容差(±0.5e,或 0.5×10^-p×√N,p=电荷小数位)`。**去掉随原子数线性放大的 ±0.05×N**(物理错)。
- **H6 QEq 不收敛**:动态 grep log 不收敛告警/迭代顶格;静态 tolerance>1e-6 或 maxiter 过小软告警。
- **H7 bondchk failed / lost atoms**:动态 grep(bondchk failed / lost atoms / atoms missing / Too many neighbor bins),出现即拦。

**软门(警示不拦)**:S1 自热预警 / S2 密度落物理区间(用 declared_density_range,中间态 0.259/0.484/0.67=碎片) / S3 弛豫温度不趋 0K(排除淬火) / S4 控温阻尼合理性(Tdamp≈100×dt) / S5 neighbor 重建 / S6 单位制与 pair_style 一致(ReaxFF 用 real)。

**纪律**:S6 明确**不写死力场键级/价态/vdW 参数**(ReaxFF 参数纪律);所有 rationale 绑本项目实测事故(70万K自热 / 密度0.259/0.484/0.67 / QEq -0.81),非编造。

## 5. 受控写的红线/安全(已修正,校验 high#2 是安全洞)

**写 MCP 只暴露两个动作**:`project_root 内 mkdir`、`写 *.json 骨架`。**固定命令模板,不接受 agent 传入任意 argv**;**绝不代理 claude_interface 的 ALLOWED_EXECUTABLES 全集**(否则 read_paper 注入面下可诱导调其它命令)。

**五道闸**:
1. **realpath 限域(不是字符串 `..` 检查!)**:目标路径 `os.path.realpath` 规范化 → 断言 `startswith(realpath(PROJECT_ROOT))` 才放行;路径任一段是符号链接则拒(或 realpath 后仍在根内)。
2. **标识符白名单**:project/case_id 只允许 `[A-Za-z0-9_\-]`,禁止 `/` 与 `..`。**来自 read_paper 的不可信文本永远不能直接当路径**,必须经此校验 + 用户确认双闸。
3. **JSON 内容写= 单列受控原语**(不是 mkdir):同样过 realpath 限域 + audit + 写前 schema 校验(拒绝把绝对路径塞进 prod_dir_ref 等越界字段)。
4. **审计**:每次写走 audit()——记 ts/actor/action/target/before/after 落 `PROJECT_ROOT/_audit/`(**不复用 AGENT_BASE 锚定的 claude_operations,否则破物理隔离**,校验 high#2)。
5. **用户确认**:首个"写"回显目标路径讲清后果再等确认;Mode B 一次迭代的建项目+建任务+写intent **批量预览一次性回显**(减确认疲劳)但保留最终 single 确认,不外推。

**results/ 回链**:只读软链,**明确禁止任何写原语穿透**(realpath 落点在 RUN_CASE_BASE 一律拒写);或干脆只在 intent.json 存字符串指针不建软链(校验 low#7)。

**边界不变**:模拟真相源(status_bus/state/logs/prod_dir/data/ffield/production.in)永远只读;写只落 PROJECT_ROOT;绝不碰 LAMMPS 计算/输入/力场/进程(红线 1/4)。

## 6. 归纳说明自动生成(接用户"每个文件夹一份归纳说明")

new_project/new_task 建夹时,同时生成 `归纳说明.md`(格式=`templates\归纳说明_模板.md` 黄金标准:数据来源/目录结构表[**文件数·大小程序实测**]/核心资产速查/注意事项);task_status/list_projects 可 refresh 它。既给用户看,也给 agent 导航(读归纳说明定位力场/数据,不 ls 海量目录)。

## 7. Mode B 五步流改造(把"理解物理意图"变可核)

① read_paper 抓四样 → ② `draft_intent` 落 intent.json(**把模型对物理意图的理解→白纸黑字规格**)→ ②.5 **用户确认门**(回显 declared_net_charge/density_range/protocol_flags/系综序列/timestep 等基准字段,ask_user 确认,status→CONFIRMED,不臆测)→ ②.9 **物理门** `validate_intent`(H1-H7 硬拦;不过则阻断、带违规回退让用户改规格;过则 GATED_PASS)→ ③ swarm 拆解**以 GATED_PASS 的 intent.json 为输入契约** → ④ 综合建模+动力学思路(草案落 inputs/,不执行)→ ⑤ 纪律。
