## 摘要(可直接改写进论文)

面向分子动力学(MD)模拟的 LLM 智能体在长周期无人值守运行中,反复踩同类报错(控温失控、电荷平衡不收敛、原子飞失、数值爆炸),而修复经验分散在官方论坛、邮件列表与 issue 区的人类专家答复中,从未被系统化地组织为智能体可用的知识源。本工作构建了一条**"爬取—清洗—打分—组织"的外部报错语料管线**(五源 6739 条问答、2982 个唯一错误签名、12246 条解法候选),并以 **"unverified 候选弹药"** 的身份将其接入智能体的自进化闭环:外部知识与自产经验走同一条毕业路——**确定性回放考场裁决**,不经考场不入环。回放考场以真实跑过且有结局的历史事件为考题(绝不重跑物理模拟),在 80 事件首考上给出诚实基线:11 个候选策略零毕业,量化暴露出修复工具箱对三大根因(extreme_temp / QEq_instability / general_instability)的真实亏空——这一诊断直接驱动了外部知识层的立项。系统进一步以三轴确定性分类(课题/方法/运行)、毕业阶梯(原子→场景→知识卡→skill→子 agent)、在岗 Beta 后验强化构成完整进化回路,全部裁决环节零 LLM token。

## 一、外部知识获取:分子模拟报错语料(A 主题)

### 1.1 动机:为什么爬论坛而不是生成

MD 智能体的修复知识有三个candidate来源,各有致命缺陷:

| 来源 | 缺陷 |
|---|---|
| LLM 参数化知识 | 对具体版本/体系/参数组合的报错幻觉率高;"看起来合理"的修复在物理上常是错的 |
| LLM 自合成经验("做梦") | 烧 token;且合成题的物理假设本身可能错——出题人都没跑过 |
| **人工专家论坛答复** | **真实(维护者亲手解决过)、带结局(标记 accepted)、免费(Wayback/公开列表)——但从未被组织** |

选第三条路:把人类专家在 matsci.org、GROMACS 论坛、gmx-users 邮件列表、GitLab/GitHub issue 里二十余年积累的报错处置经验,爬取并组织成按**错误签名**检索的结构化语料。

### 1.2 五源爬取

| # | 源 | 引擎 | 规模 | 采集方式 |
|---|---|---|---|---|
| 1 | matsci.org LAMMPS 版 | LAMMPS | 1871 条有解 | Wayback Machine 快照逐帖回放 |
| 2 | GROMACS 官方论坛 | GROMACS | 3699 条有解 | 论坛导出 |
| 3 | gmx-users 邮件列表(2000–2019) | GROMACS | 并入上 | mbox 归档逐信解析 |
| 4 | GROMACS GitLab issue | GROMACS | 并入上 | issue+评论 |
| 5 | LAMMPS GitHub issue | LAMMPS | 并入 1 | issue+评论 |

合计 **5570 条有解记录 + 1169 条无解记录**;解法候选 **12246** 条,其中 **3966** 条来自维护者(maintainer)回复。语料按**错误签名**(对报错行做归一化提取的指纹)组织,共 **2982 个唯一签名**。

### 1.3 清洗与解法打分

每条记录 = (错误签名, 问答对, 解法候选列表)。解法打分规则:

```
score = +4 若所在回答被标记 accepted(提问者确认解决)
        +3 若回复者是维护者
        +1 若正文含可执行命令/参数修改
        −1 若正文为纯追问(无信息量)
每签名取 top-3 解法;跨源同义签名去重
```

设计意图:让"提问者确认 + 维护者背书 + 可执行"三者叠加的解法排在前面,纯社交性回复沉底。**但打分只是排序,不是认证**——所有解法在下游一律按 unverified 处理(见 §2.2)。

(加粗三类 = 与本系统回放考场暴露的三大根因直接对应的"疼痛类别",共 730 条,是外部知识层首批供弹对象。)

## 二、外部知识接入自进化系统的设计(A→B 的桥)

### 2.1 落位与检索缝

语料落盘为 `external_corpus/`(L0-EXT 层,只读),检索通过一个**确定性检索缝** `corpus_lookup.py`:

```
corpus_lookup.py "ERROR: Lost atoms ..." [--engine lammps|gromacs] [--top N]
→ 命中签名 / 中文类别 / 最优解摘要 / 原帖 url
```

实现为签名归一化 + token 打分(报错行片段加权),纯代码、零 token、绿区只读、永不写语料。找不到就返回空退出,**绝不猜测**。

### 2.2 核心纪律:unverified,经考场入环

外部知识的信任模型是本文的关键设计决策:

> **外部知识经考场入环,不经考场不入环。**

- 语料整体标记 unverified;检索返回是**参考不是命令**,不得直接执行其中写操作;
- 修复动作仍走系统既有的红区双闸(审批门 + 执行门);
- 外部解法要影响系统行为,必须走三步:**蒸馏成 spec_\* 策略候选 → 回放考场裁决(§3.3)→ 实弹验证**,胜出后才升格 `reviewed=true`。

动机:外部专家经验解决的是"他机的相似体系",与本机体系/版本/参数组合存在不可忽视的分布差;直接入环等于给未经检验的写操作开后门。该纪律与系统对自产知识的毕业要求**完全同构**——外部知识没有特权通道。

### 2.3 图谱可视化接入

进化图谱(web 端 WebGL 图)新增 L0 层:语料源节点 + 12 个类别节点(橙色 polar 层),类别到三大根因考场节点连"**供弹**"金边(体系爆炸→general_instability/atomic_ejection、温控与压控→extreme_temp、电荷与自由能→QEq_instability),使"外部弹药→考场→入环"的供应链在界面上可视。

## 三、自进化闭环(B 主题)

### 3.1 分层记忆底座

```
L0-EXT 外部语料(5570 条,unverified 候选弹药)
L0 原始层   事件流水(_flowgate.jsonl / LEDGER.jsonl),只读不写
L1 原子层   atoms.jsonl —— 一条=一个失效/修复事实,带 refs 指回 L0(现 527 条)
L2 场景层   同签名原子聚成复发场景(现 77 个),挂历史修复结果
L3 规则层   SOP.md(77 条规则)+ 蒸馏卡片(57 张)
```

纪律:压缩必须可溯源(下层存证据、上层存结构);SOP 全量确定性重建、绝不增量涂抹;撤回/取代不删本体(retracted/superseded_by),审计不灭迹。

### 3.2 三轴确定性归类

每条原子打三轴标签(课题 topic / 方法 method / 运行 ops),决定其"归宿"(课题→课题子 agent;方法→skill;运行→skill 或子 agent):

- 纯代码实现:受控词表 + 词边界/子串双模式匹配,实测 **3 万条/s**,零 token、可审计、无幻觉面——与 LLM-as-tagger 路线形成对照;
- **认证轴/候选轴分离**(防灌水关键设计):自由提取通道(case_id 正则)命中的课题只进 candidates,不参与毕业资格审查;只有受控词表归并的才是认证课题。类比密码学"不可信输入不得进安全域";
- 入账自动打标,打标器故障不阻断入账(记忆层可用性优先);
- 三路红队(代码/语义灌水/文件系统)12 项对抗发现全部修复并配回归测试,压测抓获正则回溯炸弹等 3 个真缺陷。

真账本画像(527 原子):exam_ready 283;修复救援类经验最厚(repair-rescue 295)——第一个够格开考场的方法域。

### 3.3 回放考场(评估回路,零 token)

**考题**只来自真实跑过且有结局的历史事件(kit strategy_db 的 history,只收 success/fail 结局),时序 80/20 切 seen/holdout。**绝不重跑 MD 模拟**——重跑=纯烧算力且不产生新信息;也**不合成题**——出题人的物理假设本身可能是错的。

考生为(根因, 策略)对;进留出集前必须过 `verify_refs`(refs 可核验到 L0 快照的存在性检查——堵虚构修复通道)。判分:hit_rate(对真实成功的覆盖)/ fp_rate(出手未成比例)。毕业线 hit≥0.8 且 fp≤0.1。

### 3.4 首考诚实基线与诊断价值(论文的核心实证段)

80 事件、11 考生、**零毕业**——这不是评估器失败,而是考场把系统的真实短板量化了出来:

| 发现 | 数字 | 解读 |
|---|---|---|
| checkpoint_restart 对 QEq/general_instability | hit 1.0 但 **fp≈0.94** | 重启成功≠根因治愈,同因 7 天内复发 |
| checkpoint_restart 对 extreme_temp | **25 发 0 中** | 该根因无可用武器 |
| checkpoint_restart 全场 | 76/80 次尝试押注,胜率 **0.05** | 选路层在只有一把扳手的工具箱里反复挑那把扳手 |
| 三支 spec_* 新策略候选 | untested,从未开火 | 有弹药但选路层不认识 |

结论:**弹药供应链断供**(工具箱亏空 + 选路盲区),而非评估器问题。该诊断直接驱动 §一的外部知识层立项——这是一个可写进论文的完整因果链:**评估回路的首要价值不是发毕业证,而是暴露系统在哪些根因上"不知道自己不会"**。

### 3.5 毕业阶梯与在岗 RL(设计,待落地)

```
原子 ──厚度──▶ 场景 ──蒸馏──▶ 知识卡 ──▶ skill ──▶ 子 agent(领域专家)
              每级晋升过对应考场:
              L3 毕业 = 回放考场(纯代码,已落地)
              L4 毕业 = 截断考场(VCR 式决策点单发,烧 LLM,分级毕业)
              毕业后 = 在岗 RL(新任务结局归因到建议者,Beta(1,1) 后验,连败回炉)
```

双回路进化:离线回路(回放考古,零边际成本)+ 在线回路(生产任务结局归因,任务本来就要跑,零额外算力),两回路共用同一证据账本。五条件毕业(厚度≥5 张 reviewed 卡、hit≥0.8、30 天无撤回、≥3 子场景、在用计数)。

## 四、分子模拟域的特殊性(为什么通用方案在此要改写)

| 域特性 | 对进化系统的设计约束 | 本系统对策 |
|---|---|---|
| **评估极贵**(单次模拟数小时~数天) | 在线试错不可行;"跑一遍看看"成本高到不可接受 | 回放-only 评估:考题=历史事件,零边际成本 |
| **修复=危险写操作**(改力场/参数/重跑) | 错误修复可能毁掉数天算力 | 红区双闸(审批门+执行门);外部语料解法只作参考 |
| **物理正确性不可编译验证** | 无单测式绿灯;restart 恢复"能跑"≠"对" | 结局信号必须带物理语义(复发检测、同因时间窗) |
| **报错长尾且版本敏感** | 通用 LLM 知识覆盖率不足 | 按错误签名组织的外部语料 + 确定性检索缝 |
| **经验跨体系迁移有险** | 他机解法直接搬用危险 | unverified + 经考场入环(§2.2) |

## 五、度量卫生:僵尸账污染教训(诚实性段落,审稿人好感项)

首考 94% 复发率的账面数字一度被同一 case 的机械刷单污染:一个已完成但未关账的 case 以 ~9 分钟/条的速率刷假失败账(看门狗误判进程死→恢复失败→循环)。治理采用**机械剔账规则**:仅剔除可证实的机械刷单(同 case 同签名高频循环),真实败账一律不动;并对"已完成未关账"状态做终态关账修复。

教训(可写进 discussion):**进化系统的评估指标会先于系统本身腐烂**;任何后验计数(RL 信号、毕业审查)上游都必须有度量卫生层,否则 Beta 后验会被僵尸账推向系统性错误。
